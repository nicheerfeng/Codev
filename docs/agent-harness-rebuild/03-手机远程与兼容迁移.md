# Codev Agent Harness 重构方案三：手机远程、主从架构与兼容迁移

## 文档定位

本文件是第三段方案。第一段建立 Rust Agent Host，第二段建立统一桌面 Agent UI。本段把 Host 扩展为真正的主从架构，让桌面 WebView、手机浏览器和未来原生客户端都成为同一套服务的客户端，同时完成旧会话、旧配置和旧工作区状态的兼容迁移。

本段参考 Picot 的 `host_server`、`host_router`、`remote_auth`、`runtime_coordinator`，吸收 Codeg 的独立 server、token 鉴权、WebSocket 事件广播和移动端部署经验，但不直接搬入 Codeg 的大规模业务系统。

## 一、最终目标拓扑

```text
                         ┌────────────────────┐
                         │  手机浏览器 / App    │
                         │  Remote Client      │
                         └─────────┬──────────┘
                                   │ HTTPS / WebSocket
┌────────────────────┐             │
│ Codev Desktop UI   │──────┐      │
│ Tauri WebView      │      │      │
└────────────────────┘      ▼      ▼
                    ┌────────────────────────┐
                    │ Codev Agent Host        │
                    │ Rust + axum + tokio     │
                    │                        │
                    │ Session / Runtime      │
                    │ Event Broadcast        │
                    │ Permission Broker      │
                    │ Workspace Data         │
                    └──────────┬─────────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
        Pi native RPC     ACP harnesses    文件 / 终端能力
```

默认安装版只绑定本机回环地址。用户明确开启远程功能后，才允许局域网监听。外网访问先不绑定第三方云中继，后续可以增加自建服务器或安全隧道。

## 二、主从职责

### 1. 主进程 Agent Host

Host 是唯一的状态权威，负责：

- 代理进程启动、停止、重启和崩溃处理。
- 会话和工作区绑定。
- 消息事件和运行状态广播。
- 请求去重和事件序列。
- 审批、询问和扩展 UI 请求。
- 会话历史索引。
- 设备配对和权限。
- 手机与桌面同时操作时的串行化。
- 必要的文件、Git 和终端远程操作边界。

### 2. 从客户端

所有客户端只负责：

- 获取 Host 快照。
- 发送用户操作。
- 渲染事件。
- 保存纯界面状态。
- 断线重连和重新订阅。

桌面客户端和手机客户端不能各自决定“这个会话是否运行”或“当前 turn 是否结束”。

## 三、传输协议

### 1. WebSocket 主通道

采用 Picot 的单通道思路，路径规划如下：

```text
GET /v1/health
GET /v1/bootstrap
GET /v1/ws
GET /v1/sessions
GET /v1/workspaces
POST /v1/pair/request
POST /v1/pair/claim
POST /v1/pair/approve
```

WebSocket 建立后先发送：

```json
{
  "type": "client.hello",
  "protocolVersion": 1,
  "clientKind": "desktop",
  "clientId": "..."
}
```

服务端返回：

```json
{
  "type": "host.snapshot",
  "protocolVersion": 1,
  "serverId": "...",
  "workspaces": [],
  "sessions": [],
  "runtimes": [],
  "subscriptions": []
}
```

之后所有事件带 `sequence`。客户端发现序号断裂时，发送 `host.resync`，不能自行拼接缺失状态。

### 2. 请求路由

每个请求必须有：

```text
requestId
clientId
sessionId（需要时）
operation
payload
```

Host 对操作分类：

```text
Runtime：发消息、停止、重启、切换思考等级
Session：创建、恢复、归档、重命名、删除
Data：文件读取、工作区信息、历史搜索
Approval：允许、拒绝、始终允许
Host：配对、设置、连接状态
```

手机端只开放白名单内的最小操作，不直接拥有任意文件系统命令或任意 Tauri IPC 权限。

## 四、设备配对和认证

### 1. 默认安全状态

- 默认关闭局域网监听。
- 默认只绑定 `127.0.0.1`。
- 开启远程前必须在桌面设置中明确确认。
- 远程监听端口可配置，但不自动暴露公网。
- 所有远程请求必须经过认证。

### 2. 配对流程

参考 Picot 的设备请求模式：

1. 桌面生成一次性 `requestId` 和随机 claim secret。
2. 界面显示二维码或短连接信息。
3. 手机扫描后提交设备名称和 claim secret。
4. 桌面显示待审批设备。
5. 用户点击允许。
6. Host 签发设备 token，只在配对响应中返回一次。
7. Host 只保存 token 的哈希值，不保存明文。
8. 后续请求使用 Bearer token 或 WebSocket 子协议传输 token。

错误次数、超时、设备吊销和设备列表都由 Rust 管理。

### 3. 权限分层

第一版只设两类：

- `desktop`：本机桌面，完整权限。
- `remote`：手机/浏览器，只能访问白名单操作。

远程端默认不能：

- 修改全局代理配置。
- 安装 harness 或扩展。
- 任意执行终端命令。
- 读取未绑定工作区的任意路径。
- 删除运行中的会话。

审批请求仍然由 Agent Host 统一产生，桌面和手机可以订阅，但只能有一个客户端确认成功。

## 五、手机端产品范围

### 第一版手机功能

- 查看项目列表。
- 查看会话列表和状态。
- 查看流式对话。
- 发送文本消息。
- 停止当前任务。
- 处理工具审批。
- 处理结构化问题。
- 查看当前模型和思考等级。
- 查看最近工具调用和错误。

### 暂不开放

- 完整文件编辑器。
- 多视口拖拽布局。
- 任意终端。
- 任意 Git 写操作。
- harness 安装和配置。
- 大量图片和二进制文件传输。

手机端可以复用 Agent UI 的消息模型和事件模型，但不能简单把桌面页面缩小。它需要独立的移动布局：会话抽屉、对话主面板、审批底部抽屉和文件只读查看。

## 六、会话和历史兼容

### 1. 原生历史不迁移

每个 harness 继续保留自己的原生历史：

- Pi JSONL 继续由 Pi 管理。
- ACP agent 的历史由 agent 或 ACP adapter 管理。
- Codev 元数据数据库只保存绑定关系、索引和设备信息。

历史扫描结果建立：

```text
SessionBinding {
  sessionId
  workspaceId
  harnessId
  nativeSessionId
  nativeSessionPath
  title
  lastSeenAt
  resumable
}
```

### 2. 旧 Pi 会话

旧 Pi 会话首次启动时按原有目录结构扫描：

```text
~/.pi/agent/sessions/<workspace-encoded>/*.jsonl
```

新 Host 为它们生成稳定 `sessionId`，保存原始路径。打开历史时先加载静态摘要；用户点击继续时才启动 Pi RPC 并执行 `session/load` 或 `--session` 恢复。

### 3. 旧 Codex 和 Antigravity 会话

如果旧 harness 能提供稳定的恢复入口，则建立对应绑定。如果只有历史文件、没有可恢复协议，则显示“只读历史”。不伪造可恢复状态。

### 4. 旧 Codev 插件状态

旧插件 store 中的项目目录、会话顺序、上次模型和思考等级不直接作为新运行时真相。迁移器只读取它们，用于：

- 预填工作区。
- 选择最近项目。
- 尝试匹配旧会话标题和路径。

迁移完成后，新 UI 使用统一 session binding 和 host preferences。旧 store 文件不立即删除，确认迁移稳定后再按回收站规则清理。

## 七、独立服务器模式

第三段后半部分再增加 Codeg 风格的无头模式：

```text
codev --server
codev --server --host 127.0.0.1 --port 3080
```

服务器模式与桌面模式共用 Agent Host，不启动 Tauri WebView。它需要：

- 静态 Web UI 服务。
- token 初始化和终端输出提示。
- 工作区根目录配置。
- 会话和运行时持久化。
- 关闭信号处理。
- 子进程树回收。

服务器模式不应该在第一版手机功能之前实现。先证明桌面进程作为 Host 可以支持多个客户端，再抽取无头入口，避免同时处理窗口和服务器两种生命周期。

## 八、第三段实施顺序

1. 将桌面 WebView 接入本地 WebSocket。
2. 实现快照、序列号和重连。
3. 实现本机回环地址上的浏览器客户端验证。
4. 实现设备请求、批准、吊销和 token 哈希。
5. 实现手机最小页面。
6. 让桌面和手机同时查看同一会话。
7. 让桌面和手机同时操作审批，验证重复确认不会重复执行。
8. 迁移旧 Pi、Codex、Antigravity 历史索引。
9. 再评估独立 `codev-server`。
10. 最后清理旧配置入口和迁移器临时代码。

## 九、失败恢复和一致性要求

### 1. Host 崩溃

- 子进程由 Job Object 或跨平台等价机制管理。
- Host 重启后扫描运行实例和原生历史。
- 不能把“之前运行中”直接显示为“已完成”。
- 需要通过恢复协议重新确认状态。

### 2. 手机断线

- 不影响正在运行的 turn。
- 手机重连先拿快照，再订阅新事件。
- 事件积压超过缓存时，服务端返回 resync，而不是发送无限历史。

### 3. 双端同时发送

- 同一 session 同时只能有一个 active turn。
- 第二个发送请求返回明确的 busy 状态或进入队列。
- requestId 去重。
- 审批回应只允许第一次有效回应。

## 十、第三段完成标准

- 桌面和手机能够连接同一个 Rust Host。
- 手机断线重连后可以恢复会话快照。
- Pi 和至少一个 ACP harness 可以通过同一套远程协议操作。
- 设备 token 不以明文持久化。
- 默认不暴露局域网端口。
- 远程接口不存在任意 IPC 或任意路径访问。
- 旧 Pi JSONL 可以被发现并按原生语义恢复。
- 不支持恢复的历史明确显示为只读。
- 独立服务器模式不会复制一套 Agent 运行时。
- 只进行编译、静态协议、鉴权逻辑和界面诊断；手机真实联调与模型消息发送在审核阶段执行。

## 十一、最终架构取舍

最终不选择“整体复制 Codeg”，也不选择“只做 Picot 桌面遥控”。采用联合方案：

```text
Picot 提供：
  Rust 运行时、Pi 原生桥、ACP 管理、RuntimeCoordinator、WS Host、设备认证骨架

Codeg 提供：
  多 harness 注册思想、独立 server、多客户端广播、历史索引和 token 控制经验

Codev 提供：
  右侧统一 Agent UI、文件阅读工作台、多项目多根目录、终端、多视口、主题和窗口体验
```

最终原则：

- Pi 是一等 harness，不是 ACP 模型 provider。
- ACP 是其他 harness 的接入协议，不是跨 harness 模型转发层。
- Agent Host 是唯一运行时主进程。
- 桌面和手机是客户端，不各自维护代理状态机。
- SQLite 只保存 Codev 自己的元数据和索引，不替换各 CLI 的原生会话真相。
- 多视口是 UI 布局能力，不是第二个运行时中心。
- 统一的是协议、事件和能力描述，不是强行统一每个 agent 的内部语义。
