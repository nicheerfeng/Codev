## 结论状态

三段方案的主体开发已完成：Rust 主机、统一桌面界面、手机连接与独立服务入口均已落地。当前进入人工审核阶段。自动验证只覆盖类型、编译、构建、代码检查和静态诊断；真实代理会话、登录与手机联调尚未执行。

## 第一段：Rust Agent Host

已完成：

- `src-tauri/src/modules/agent_host/`：协议、运行目标、协调器、桥接、Pi 原生会话、ACP 会话、元数据、历史、权限、认证、服务。
- 每个会话一个受监督进程；重启更换运行实例，旧实例事件和请求不能写入新实例。
- 事件带单调序号；客户端断线重连使用快照，消息以增量 patch 推送，实时视图有内存与大小上限。
- 请求去重限定在单个设备与主机生命周期内；队列长度、图片数量和总大小均有限制。
- Pi 直接使用 `pi --mode rpc`，恢复使用原生 `--session` 路径，不发送 ACP 的 `session/load`。
- ACP 代理使用独立进程，初始化能力决定审批、图片、思考等级和模型控件；不向 Pi 注入其他代理模型。
- SQLite 仅保存工作区、会话绑定、偏好和设备令牌哈希；原生 JSONL 不被改写。
- 退出、窗口关闭和独立服务中断都会回收子进程树。

## 第二段：统一桌面界面

已完成：

- 右侧统一 Agent 入口：项目会话栏、单行标题、运行状态、新建会话、会话侧栏、多视口、设置。
- 能力驱动控件：模型、思考等级、权限模式、图片、文件引用、队列、压缩、扩展请求；不支持时不显示假按钮。
- Pi 原生历史按父链读取，分段加载；Codex 原生历史只读展示；旧 Antigravity 绑定导入后由真实 `loadSession` 决定能否恢复。
- 多视口最多六格，按住标题移动六像素后交换内容，Escape 取消；关闭视口不停止代理。
- Pi 分叉使用原生 `clone`，保留最后一轮；在确认生成独立会话文件前保持只读，避免损坏源会话。
- 旧 Pi 界面特征回归：执行过程折叠与步骤/工具数、运行耗时、文件路径芯片与只读预览、对话内搜索与上一个/下一个命中、输入历史上下键回溯、压缩中提示、队列预览、阅读位置恢复、回到最新。
- 旧 Pi、Codex、Antigravity、Workbench 插件已退出入口、依赖图、类型检查、代码检查和测试入口。
- 公共语音能力从旧插件分离到 `src/modules/voice`，沿用既有配置存储，桌面输入区与设置可用；手机不启用。

## 第三段：手机远程与兼容迁移

已完成：

- 桌面和手机共用同一 WebSocket 协议与主机快照；桌面通过唯一原生命令取得本机地址和临时令牌。
- 手机页面 `mobile.html`：二维码、六位配对码、桌面批准、设备令牌、会话选择、消息、停止、审批、模型与思考等级、绑定工作区文件只读预览。
- 设备令牌只保存 SHA-256；可撤销；断开后连接按心跳退出。
- 默认只监听回环地址；手机连接需在桌面显式开启，局域网 HTTP，公网需自备 HTTPS 入口或隧道。
- 远端快照移除本机启动命令、参数和原生会话路径；远程客户端不能安装代理或调用任意 Tauri 命令。
- 独立入口 `codev-server` 复用同一主机，不启动桌面窗口；支持 `--host`、`--port`、`--workspace`、`--data-dir`、`CODEV_WEB_DIR`。
- 旧项目列表、旧 Antigravity 会话标题与原生标识一次性导入；旧存储保留，不删除用户配置。

## Codex 与 Antigravity 接入情况

Codex：

- 默认注册 `acp:codex`，启动程序为固定的 `@agentclientprotocol/codex-acp@2.6.0`。
- 新增 `pnpm agent:prepare`：把适配器安装到用户缓存下的独立版本目录，使用其自带的固定 Codex 依赖，不修改全局 npm 配置，不自动登录。
- 主机启动时优先使用该独立目录；缺失时回退到 `npx`，并支持 Windows 的 `.cmd`、`.bat`、`.ps1` 启动包装。
- 适配器声明支持 `loadSession`、图片与嵌入上下文；实际能力以每次 `initialize` 返回为准。
- 未登录时错误信息会提示在原生命令行完成 `codex login` 或使用 API Key，不在 Codev 内收集凭据。

Antigravity：

- 注册 `acp:antigravity`，直接启动本机 `agy acp --stdio`，使用 CLI 自己的认证与配置。
- 已验证本机 `agy 1.5.11` 支持 `acp --stdio`、`--login`、`--process-per-session` 等参数。
- 未登录或认证失败时提示在 Windows CMD 中运行 `agy` 完成登录；Codev 不读取、不保存其凭据。
- 旧 Antigravity 会话通过旧应用存储导入原生会话标识，恢复失败时保留绑定并给出真实错误，不伪造历史。

## 已知边界与待人工反馈

1. **Codex**：需要本机已有 Codex 登录或 API Key；适配器首次准备依赖网络，失败时仍可用全局 `npx` 回退。
2. **Antigravity**：CLI 登录状态和 Google 账号策略由 CLI 决定；ACP 会话恢复能力取决于其返回的 `loadSession`。
3. **Pi**：模型、思考等级和命令来自当前原生运行时；旧 `models.json` 编辑界面未迁入，需在 Pi 原生命令行或配置文件中修改。
4. **历史**：Codex 原生历史只读；没有历史回放能力的 ACP 代理不显示伪造的历史。
5. **手机**：当前为局域网 HTTP；若要公网使用，需要自行提供 HTTPS 反向代理或安全隧道。原生 iOS/Android 应用未实现。
6. **旧目录**：系统权限拒绝删除与重命名，旧源目录原位保留但已隔离；不在应用内出现，不参与构建。
7. **编辑上一条**：旧 Pi 的“编辑最后一条用户消息”依赖截断原生会话并重发，本轮未移植，避免损坏 JSONL；当前提供按消息分叉。

## 审核窗口检查清单

1. 设置 → 插件：确认“Agent 工作区”已开启。
2. 右侧 Agent：选择工作目录，顶部选择 Pi，新建会话，确认模型与思考等级来自 Pi 原生运行时。
3. 发送一条消息，观察流式回复、执行过程折叠、耗时、工具状态、文件芯片、搜索与输入历史。
4. 停止任务；运行中再发送一条，确认进入队列并自动续发。
5. 空闲时复制当前会话，确认生成保留最后一轮的分叉。
6. 新建 Codex 会话：首次可能准备适配器；若未登录，应看到明确命令行登录提示。
7. 新建 Antigravity 会话：确认使用本机 `agy`；未登录时应提示在 CMD 运行 `agy`。
8. 多视口：拖动标题交换内容，确认会话不重启；关闭视口后代理仍运行。
9. 设置 → 手机连接：开启端口、生成配对码、用手机扫码并输入六位码，在桌面批准；确认消息、审批、断线与重连。
10. 如有问题，请提供会话类型、操作步骤、界面提示和审核窗口日志路径，便于按真实链路修正。
