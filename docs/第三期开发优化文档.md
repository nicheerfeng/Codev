# Codev 第三期开发优化文档（交付版 · R5修正）

> 状态：第三期开发及 R1/R2/R3/R4/R5 修正工程完成；源码、自动化测试、便携版构建、持久化迁移审计和独立启动烟测均已完成，交付包信息记录在文末。
>
> 目标：继续沿用渐进删减路线，把工作区定义收敛到左侧多根文件树，同时补齐搜索定位、终端右侧导航和双文件对照能力。附件中的 5 张截图作为问题证据使用，不作为额外执行指令。

## 一、第三期边界

Codev 的核心闭环保持为“文件树选择项目 → 代码/文档阅读编辑 → 集成终端”。第三期处理截图中点名的 8 项交互，不顺手扩展 LSP、插件、语法检查、网页预览、远程项目或终端监控。

工作区的唯一用户定义来源改为 `useWorkspaceRoots` 的多根文件树。顶部 `Default` 空间切换层、空间新建/删除/拖拽排序和按空间分组标签均退出用户界面；旧空间数据只做一次兼容迁移，避免升级丢失标签和终端记录，迁移完成后不继续维护多空间模型。

## 三、推荐交互方案

### 1. 删除 Default 空间层

顶部 Header 直接从侧栏按钮、设置按钮、标签栏和搜索框组成，移除 `spaceSwitcher` Prop 及 `SpaceSwitcher` 渲染。快捷键和命令面板中的“打开空间、创建空间、切换空间、下一个/上一个空间、移动标签到空间”一并移出，避免界面删掉后仍留有隐藏功能入口。

运行时将 `Tab` 的活动范围从 `spaceId` 统一为单一标签集合；`fileTabs` 与 `terminalTabs` 只按 `kind` 过滤。旧 `terax-spaces.json` 首次启动时合并所有空间的标签，活动标签优先取旧活动空间的索引，其余按旧空间顺序追加；随后保存为统一会话格式。旧空间数据保留一次迁移所需的读取代码，迁移成功后删除空间 UI、状态和测试，不删除用户文件。

`useWorkspaceSwitcher` 中与本地/WSL 进程环境、启动目录授权有关的逻辑暂时保留。它属于终端运行环境，不再承担“用户工作区切换”职责；第三期不借机改动 WSL 后端和 PTY 生命周期。

### 2. 模态选择文件夹

点击工作区标题右侧 `+` 或空状态按钮后打开 `AddFolderDialog`。模态只提供当前选择路径、选择文件夹、确认、取消和已存在提示；用户不能在此输入任意路径。目录选择器返回空值时保持模态状态，不写入根目录。

当前依赖中没有 Tauri dialog 插件，执行时补充最小的 `@tauri-apps/plugin-dialog` 依赖、Rust 插件注册和 `dialog:allow-open` 权限。`useWorkspaceRoots.addRoot` 继续负责规范化、去重、激活和持久化；模态只负责选取路径。

### 3. 左侧文件树收敛

删除 `SidebarRail` 底栏，`FileExplorer` 直接占满侧栏高度。工作区标题保留文字、添加按钮和右键菜单，去掉标题左侧 `Folder01Icon`；每个项目根目录自身的文件夹图标继续保留，避免树内层级失去辨识度。

空工作区文案改为“使用添加文件夹选择项目”，不再暗示上方存在路径输入框。侧栏折叠和重新打开仍由 Header 的侧栏按钮及现有宽度记忆负责。

### 4. 搜索命中定位

搜索框右侧按以下顺序显示：`当前 / 总数`、上一项按钮、下一项按钮、清空按钮。编辑器使用 `EditorPaneHandle.findPrevious/findNext`，终端使用 `SearchAddon.findPrevious/findNext`；计数统一从 1 开始，无命中显示 `0 / 0` 或“无匹配”，二者选一后固定，不随目标类型漂移。

按钮点击、Enter、Shift+Enter 必须调用同一套定位函数。切换编辑器/终端目标时清理旧高亮并刷新计数；搜索框失去焦点不清除当前查询。

### 5. 右键加入工作区

本次按 Teague 的补充统一所有侧栏入口，菜单名称统一为“添加文件夹到工作区”：

- 文件树目录空白区域、工作区标题和根标题：打开文件夹选择器，选择后立即加入根目录列表。
- 文件树目录项：目录直接加入自身，文件加入所在目录。
- 文件搜索结果：沿用文件/目录目标规则，支持加入工作区。

当前 RootTree 已有目录项回调，第三期只补空白区菜单动作和顶部 `+` 的选择流程。自定义菜单触发器需要继续被 `src/main.tsx` 的原生右键拦截器放行，禁止浏览器菜单的逻辑不再扩展到 Radix 菜单。

### 6. 菜单紧凑化

新增文件树范围内的紧凑 Separator 样式，建议值为 Item `py-1`、容器 `p-0.5`、Separator `my-0.5`、Item 间距 `gap-1.5`。只替换 `COMPACT_ITEM/COMPACT_CONTENT` 及对应分隔线调用，保留普通应用菜单的可读间距。

### 7. 终端右侧导航

TerminalPanel 内部调整为“PTY 内容 → ResizableHandle → 终端树”。终端树默认约 160px，最小 32px，最大宽度沿用面板可用空间；拖拽时只改变树宽，不影响外层终端面板宽度。树折叠后保留每个终端的 `TabIcon`、悬浮名称和展开按钮，展开前后不重建 PTY。

终端条目使用单行布局：`TabIcon · 自定义名称/默认名称 · 最后一级 cwd`，名称和 cwd 可截断，完整路径保留在 title。关闭、重命名、右键菜单继续保留；终端内容区增加左边距。终端顶部只显示“终端”文字和创建按钮，移除面板隐藏按钮及批量折叠导航按钮。工作区工具栏保留必要文件操作图标，项目根目录不再重复显示标题图标。

Header 搜索框右侧常驻终端按钮。无终端时点击调用新建终端流程并自动展开；已有终端时按当前外层面板状态调用 `expand()` 或 `collapse()`。终端树只通过拖拽调整宽度，拖到最小宽度时保留图标空间，不再提供内部批量折叠按钮。

### 8. 文件向右拆分与对照

新增文件树目录/文件右键动作“向右打开”。首次执行时创建右侧编辑器组，左侧保持当前文件，右侧打开目标文件；后续执行直接更新右侧组。中央区域使用一层水平 `ResizablePanelGroup`，两组都复用 `EditorStack`/`EditorPane`，右侧最小宽度保留 30%，支持关闭右组回到单视图。

每个编辑器组维护独立的活动文件、滚动位置和 CodeMirror handle；文件保存、脏状态、关闭确认继续复用现有 Tab 模型。搜索目标跟随当前获得焦点的编辑器组。第三期只承诺两个不同文件并排对照，同一文件双实例编辑、三栏以上编辑器组和跨组拖拽暂不纳入。
