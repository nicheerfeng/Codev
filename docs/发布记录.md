# Codev 发布记录

> 所有正式版本和待发版变更集中记录于此。创建 GitHub Release 时，优先从对应版本条目复制说明，避免遗漏修复范围、验证结果和交付文件。

## 记录格式

每个版本固定记录：

- 版本与标签：`Codev x.y.z` / `vx.y.z`
- 发布日期：使用 `YYYY-MM-DD`
- 变更摘要：用户可感知的功能和修复
- 兼容性说明：数据、配置、系统或升级注意事项
- 验证结果：类型检查、测试、构建和实际烟测
- 交付文件：正式文件名、平台和 SHA-256
- 已知问题：只记录未阻断发布的事项

## Codev 0.8.8

- 发布日期：`2026-09-01`
- 变更摘要：新增独立 JSON/JSONL 格式化插件；设置页收敛为“常规 / 插件”两个 Tab；格式化工具支持自动识别粘贴内容、双页横向对照和内部统一搜索；搜索命中同步适配高对比文字色；长 JSON 行按视口自动换行；搜索栏宽度收窄至格式化页可用宽度的 50%。

- 交付文件：`Codev-0.8.8-Windows-x64-Portable.exe`（7,676,416 bytes，SHA-256：`3FA4779BFABFAFB6554AD3DFD1D78F5B3218C50638D880852F77E9B935504AE1`）；`Codev-0.8.8-Windows-x64-Setup.exe`（4,195,709 bytes，SHA-256：`FE158F61FA434A60FF4D409DE35EF578B3B69272A689368177358EA06986F971`）。

## Release 使用流程

1. 完成开发后，将“待发版”改为正式版本条目。
2. 补录测试命令、构建产物、SHA-256 和已知问题。
3. 将该版本条目的“变更摘要”和“兼容性说明”用于 GitHub Release 描述。
4. 发布后保留 Git 提交、标签和最终资产名称，下一轮重新建立新的“待发版”条目。
