## r10 会话操作与输入命令

- 依据本机 `@earendil-works/pi-coding-agent@0.85.0` 的 `rpc-types.d.ts`、`rpc-mode.js` 和 `session-manager.d.ts` 核对协议。全部功能继续使用现有 Rust 通道。
- 停止：`clear_queue → 恢复队列文字 → abort → get_state`；最后一条输入可取回编辑，保留原输入图片与当前草稿。取回编辑后再次发送属于新的输入记录，原消息不被删除。
- 消息：读取原生 message.timestamp 显示本地时间，悬停显示完整日期时间；正文复制不带时间或操作按钮。回复旁的分叉入口通过 `get_entries` 父链找该轮输入，交由原生 `fork`，恢复原文到新线程草稿。
- 克隆：右键线程或 `/clone`，使用原生 clone 复制活动分支。客户端为新会话分配新 key，保留源线程条目及历史，避免操作后源线程被覆盖。
- 会话树：右键线程或 `/tree` 按需读取 `get_tree`；支持筛选、每批 100 项与输入节点分叉。Pi 当前 RPC 未暴露 navigateTree，不提供虚假的原地切换入口。
- 输入：`/compact [说明]` 直接调用 compact；`/fork` 打开分叉输入列表。`get_commands` 的扩展、提示词、技能命令按原名称发送。菜单支持上下选择、Tab/Enter 补全与 Escape 关闭。
- 核验：类型检查与生产构建通过；68 个测试文件、388 项通过。后台 Chrome fixture 覆盖复制、时间戳、停止与队列恢复、最后输入编辑、分叉后原线程保留、克隆、压缩 RPC 路由、会话树以及 480×620 深色窄窗；页面异常为 0。局部 lint 无错误，仍有项目既有风格类别警告。

## r9 错误归属与发送滚动修复

- 原因：PiAgentPane 的单一 notice 字符串接收所有线程操作错误和扩展通知，不含来源，旧错误会在切换后继续显示。Rust 的“工作目录不存在”来自启动会话时的 cwd 检查；显示在别的线程是前端提示串线。
- 修复：提示以线程 key 隔离，异步失败使用发起操作的 key；新建失败归属新线程，右键目标操作归属目标线程；通知与 view.error 均进入 PiComposer 同宽居中区域，关闭时清理当前错误。
- 原因：阅读/搜索暂停 follow 后，submit 不会重新启用；输入卡片高度变化也会改变视口大小。
- 修复：每线程的主动发送修订号触发恢复 follow，清除残留搜索定位；监听视口尺寸，下一帧仅在 follow 状态滚动到底，不覆盖用户主动翻阅。
- 核验：67 文件/383 测试通过；Chrome 模拟延迟 1800ms 的不存在项目错误，切换正常线程后无提示污染；原线程可查看并关闭错误；扩展通知隔离通过。
- 滚动核验：文字发送后 gap=0、连续流式输出 gap=0、搜索后粘贴并发送 800×600 图片 gap=0；主动上滚后追加输出 scrollTop=15277→15277；未捕获页面错误。
