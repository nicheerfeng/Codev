# Codev Pi Agent 插件执行规划

## 1. 目标与边界

在 Codev 右侧 Dock 增加可关闭的 `Pi` 页面，让用户在当前工作区中创建、恢复和控制 Pi Coding Agent 会话。界面提供流式对话、工具调用状态、模型/思考等级、停止、继续指令与基础线程管理。

本期不实现远程访问、多用户、通用 Agent provider、Agent 商店、Git worktree 管理、独立文件树、独立终端、权限沙箱或 Pi 配置编辑器。Pi 的凭据、模型、扩展、技能与会话文件继续由 Pi 自身管理。

## 2. 架构决策

### 2.1 运行模型

每个活动 Pi 会话对应一个由 Rust 管理的 `pi --mode rpc` 子进程。Rust 使用标准 stdin/stdout 管道发送和接收严格 JSONL；stderr 单独转成诊断事件。RPC 进程不占用 xterm/ConPTY，也不复用终端 PTY。

### 2.2 分层

```text
PiAgentPane (React)
  ├─ session list / header / transcript / composer
  ├─ Zustand view state + pure event reducer
  └─ invoke + Tauri events
           ↓
src-tauri/modules/pi_agent
  ├─ executable resolver
  ├─ process registry
  ├─ strict JSONL reader/writer
  └─ lifecycle + event emitter
           ↓
pi --mode rpc --session/--name
           ↓
~/.pi/agent configuration and sessions
```

### 2.3 资源策略

- 插件默认关闭：不渲染面板、不扫描会话、不启动 Pi。
- 第一次进入 Pi 页面时才查询可执行文件和会话。
- 一个会话最多一个 RPC 进程；切换 UI 不重复启动。
- 关闭会话页面只释放视图；明确结束或应用退出时关闭子进程。
- 消息列表使用现有 `@tanstack/react-virtual`，只渲染可视消息。
- Markdown 使用项目已有 Streamdown；代码、图标、主题和滚动条全部复用 Codev 组件。
- 不增加 Next.js、Fastify、node-pty、Electron、Expo、Monaco 或第二套 xterm。

## 3. 状态模型

### 3.1 Native 会话状态

`starting → idle ↔ running → stopping → stopped`，任意阶段可进入 `failed`。每条 native 会话记录包含：内部 ID、cwd、Pi session file、进程 ID、stdin、最新状态和退出原因。

### 3.2 前端会话状态

前端按 native ID 建立实体表，保存消息、流式草稿、工具调用、队列、模型、thinking level、context 使用量和错误。当前工作区只展示 cwd 与根目录一致的会话。

### 3.3 RPC 相关性

每个命令携带递增 request ID。`response` 只处理命令接收结果；实际运行态由 `agent_start`、`message_update`、`tool_execution_*`、`agent_end/agent_settled` 驱动。未知事件保留原始类型并忽略展示，避免协议升级导致崩溃。

## 4. UI 结构

右侧一级 Tab：`终端 | Pi | JSON格式化 | 文本对照`。

Pi 页面保持三层：

1. 顶栏：线程按钮、标题、模型、思考等级、新建和运行状态。
2. 消息区：用户/助手消息、折叠工具调用、流式状态、错误提示。
3. 输入区：自适应文本框、发送、运行中追加、停止；支持粘贴多行文本。

线程列表使用面板内抽屉，不常驻占宽。当前根目录切换后加载对应会话；无根目录时禁用发送并提示先选择工作区。

## 5. Native IPC

计划提供以下最小命令：

- `pi_agent_probe`：解析 Pi 路径与版本。
- `pi_agent_list_sessions`：列出指定 cwd 的 Pi 原生会话摘要。
- `pi_agent_start`：新建或恢复 RPC 会话。
- `pi_agent_send`：发送 prompt/steer/follow_up 等协议命令。
- `pi_agent_stop_turn`：发送 abort。
- `pi_agent_close`：结束一个 RPC 进程。
- `pi_agent_close_all`：应用退出时回收进程。

统一事件 `codev://pi-agent-event` 携带 `sessionId`、`stream` 和解析后的 JSON 值；进程退出使用独立结构化事件。不会把模型密钥传给前端。

## 6. 编辑器上下文桥接

第一阶段只在用户主动操作时附加上下文：当前文件绝对路径、光标或选区、活动工作区根目录。不会定时轮询编辑器，也不会自动发送完整文件。后续是否增加打开标签列表由用户评审决定。

## 7. 开发阶段与检查点

### 阶段 A：协议与进程基础

- 新建 Rust `pi_agent` 模块、Pi 路径解析和进程注册表。
- 实现严格 LF JSONL 解析、命令写入、事件转发和退出回收。
- 使用本地假 RPC 进程测试，不调用真实模型。
- 检查点：Rust 测试通过，插件关闭时零进程。

### 阶段 B：前端状态层

- 增加 RPC TypeScript 类型、纯事件 reducer 和 Tauri client。
- 覆盖流式文本、工具开始/更新/结束、队列、结束与错误事件。
- 检查点：乱序无关事件不破坏会话；同一增量不重复追加。

### 阶段 C：最小聊天页面

- 设置页增加 Pi Agent 开关，独立写入 `codev-plugins.json`。
- 右侧 Dock 增加 Pi Tab，并沿用已修复的硬隐藏视口隔离。
- 实现消息区、输入区、发送、停止和状态反馈。
- 检查点：可在当前根目录完成一轮真实 Pi 对话，终端状态不串入 Pi 页面。

### 阶段 D：线程与模型

- 实现新建、当前项目线程列表、恢复、重命名。
- 接入 `get_available_models`、`set_model`、thinking level 和会话统计。
- 检查点：重启 Codev 后可恢复 Pi 原生线程；不同根目录不混用会话。

### 阶段 E：体验与稳定性

- 长消息虚拟滚动、工具调用折叠、自动跟随与用户滚动脱离。
- 输入排队、停止、进程异常退出、Pi 不存在和版本不兼容提示。
- 主题、选区、滚动条、窄宽度和插件切换回归。
- 检查点：持续运行、切换终端/插件和关闭应用均无孤儿 Pi 进程。

### 阶段 F：交付

- 全量 TypeScript/Rust 测试、格式检查和构建。
- 生成便携审核包；不自动启动应用，由用户手动验证真实模型和视觉体验。
- 用户确认后更新安装包、发布记录和 GitHub Release。

## 9. 稳定交付标准

- Pi 插件关闭时不产生进程和持续计算。
- Pi 0.85.x 可在 Windows 中探测、启动、发送、停止和恢复会话。
- 流式消息与工具调用可见，停止操作有明确反馈。
- 会话数据只写入 Pi 原生目录，Codev 只保存插件开关和轻量 UI 偏好。
- Pi 页面与终端完全隔离，不发生覆盖、串选或快捷键穿透。
- 无孤儿进程、无明文密钥复制、无完整 Web 服务依赖。
- `pnpm check-types`、`pnpm test`、`cargo fmt --check`、`cargo test`、`cargo check` 和 Windows 便携构建通过。

## 10. 长程恢复规则

每完成一个阶段，必须在本文对应检查点后追加：完成状态、关键提交、测试结果和未决问题。恢复开发时依次读取 `CODEV.md`、本目录 README、本文和参考快照，再从最近未完成阶段继续；禁止重新扩展范围或改用完整 Web 服务。
