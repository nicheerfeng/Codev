## 验收方式

按功能链路核验入口、状态、协议和可见结果；运行纯逻辑测试与隔离 Chrome 页面。原生拖放在独立 Tauri 开发窗口检查。使用本机现有工具，不构建安装包。每项记录结果和明确限制，不能用全部测试通过替代功能验收。

## 本轮结果与边界

- 拖放：独立 Codex store、文件树目标与原生 WebView 监听；固定落点线程；系统物理坐标按 DPI 转为页面坐标。目录标签、图片预览及历史路径点击均已接入。
- 编辑：通过 `thread/fork.beforeTurnId` 创建最后一轮之前的分支，再提交新输入；保留旧历史和既有磁盘修改。运行中仅允许原生 steer，完成后继续由 Codev 的线程独立内存队列实现。
- 队列：删除、退回编辑、立即追加、失败重试；停止恢复尚未提交项与附件。队列随插件进程保留，应用退出不持久化；未承诺跨重启恢复。
- 历史：侧栏自动读完 `thread/list` 元数据分页，不再显示全局“加载更多会话/归档”。正文使用 `thread/turns/list` 每页 30 轮、虚拟渲染及更早记录加载。搜索覆盖已加载历史，界面明确标注该范围。
- 线程管理：Markdown 导出逐页读取全部轮次；彻底删除调用官方 `thread/delete`，用户确认后执行。未直接删除原生 JSONL 或抢占写锁。
- 上下文：只展示原生 token usage；缺少 modelContextWindow 时显示 tokens，不猜占比。压缩后等待原生数据更新。
- 文件操作：按服务端 add/delete/update 展示；汇总按路径去重，删除记录定位父目录；未知工具字段仍保留原始详情。
- 后台：项目级完成通知；JSONL 目录通知合并刷新，忽略本插件正在维护线程的写入，外部空闲历史只读刷新。
- 独立性：新增 Codex 模块未导入 Pi 业务模块；公共基础 UI、文件 API 和拖放组合入口属于应用接入层。

## 最后一条输入编辑：两遍一致性核验

1. 源码对照 Pi 的 `editableLastUser`、消息操作栏与 `editLastUser` 提交：Codex 改为相同的 `PencilEdit01Icon`、13px、ghost/icon-xs、悬停操作栏；编辑框自动聚焦，取消/发送在气泡外，编辑时隐藏普通消息操作，空白不可发。
2. 反向检查生产 DOM 与原生请求：仅匹配全会话最后用户消息 ID；同轮其他输入、旧轮输入均无按钮；尾部压缩轮次不遮蔽末条；完成或终止且无助手回复仍可编辑；运行/发送/停止/排队/审批时不可编辑；提交前再次核验消息 ID，拒绝过期编辑目标。

协议差异保留：Pi 可按消息 entryId 分叉，Codex 按 beforeTurnId 分叉。Codex 同轮较早的用户输入与附件会一并保留到重发请求，工具和助手的中间执行过程仍按整轮重新生成；没有伪称原生提供消息级回滚。编辑提交期间锁定原线程输入，旧历史保持不变。
