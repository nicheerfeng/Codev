本轮针对设置说明、过程折叠、消息操作与侧栏拖拽进行对齐，不改 Pi 的业务代码。

## 本次源码对照范围

逐项比较 PiAgentPane/CodexPane、PiSidebar/CodexSidebar、PiComposer/CodexComposer、PiTranscript/CodexTranscript、两个排序 hook 和两份样式文件的交互入口、标签及事件处理。排序 hook 在替换插件名称和 data 属性后全文一致；slash 菜单使用相同容器与选项样式。已通过隔离浏览器验证侧栏排序、六视口拖放、标题同步、消息折叠及上述命令交互。

保留的协议差异：Codex 原生沙箱与资源切换、turn/steer、skills/list 及 skill 输入；不复制 Pi 的 RPC、follow-up 队列或 token 估算。技能从菜单选中后成为可移除的附件，名称和路径随原生请求提交；失败时保留，成功时清理。每次打开菜单及 skills/changed 事件均刷新，切换项目丢弃上个目录的异步结果。

后续逐项适配已补齐最后一轮编辑、搜索定位、线程管理和文件拖放等。最新范围、用户截图备注和核验限制以 [逐项适配清单](逐项适配清单.md) 为准。

## 独立性

Codex 的 UI、CSS、时间线、资源存储、会话状态、IPC 和 Rust 进程桥接均位于独立的 codex-agent/codex_agent 模块。本次直接检查这些目录，未发现 pi-agent/pi_agent 的业务模块导入。

共享项为应用公共基础设施：Button/Select/Dialog 等 UI 原语、Hugeicons、公共 MarkdownTable/ZoomableImage、uiState 文件适配器、Tauri IPC 和进程 Job Object。这些模块不持有 Pi 会话状态。样式仅使用 codex-* 作用域；Pi 的事件格式、reducer、runtime 和资源配置没有被 Codex 引用。外观参考 Pi 不等于复制整个插件或依赖 Pi 插件运行。

## Codev 与 Desktop

Codev 的 Rust bridge 自己启动 app-server，并只为自己的子进程注入资源 baseURL/key；不会复用 Desktop 的 app-server，也不会修改 config.toml/auth.json。Desktop 不需要因为 Codev 的资源选择而重启。

两者可能共享 CODEX_HOME 中的历史与线程写锁。不同线程由不同进程写入可以并行；相同线程被任一进程持有写锁时，另一个进程恢复写入会冲突。固定 provider 仅维持会话配置身份，不会消除写锁，也不代表实时同步同一线程。

设置说明对用户提供的文本做了事实校正：key 当前加密落盘，HTTPS 地址才提供加密传输；切换不重启 Codev，但会重建本插件 runtime；账号登录和第三方历史迁移没有被表述为本插件已实现的自动能力。

核验使用现有 UI 回归脚本覆盖设置“更多”、步骤统计、历史时间、fork 参数、侧栏前后拖拽和六视口；不调用真实模型。

补充核验：558 项 Vitest 通过；slash 浏览器回归验证全局/项目同名技能、禁用过滤、原生 skill 参数、项目隔离和 skills/changed 刷新。真实 CLI 在临时 CODEX_HOME 下确认全局技能 scope=user、项目技能 scope=repo，另一个 cwd 不会发现该项目技能；未发起模型调用。首次 cmd 启动初始化超时，直接 Node 启动协议核验通过；临时目录清理遇到文件占用，后续清理被自动审批阻止。
