## 二、总体架构调整(核心设计)

### 2.1 多根工作区模型(对应 R1/R2)

现状:`useWorkspaceCwd` → 单一 `explorerRoot` → `FileExplorer(rootPath)`。
改造:引入 **WorkspaceRoots(根集合)** 概念:

```
useWorkspaceRoots (新,src/modules/tabs/lib/ 或 workspace/)
 ├─ roots: WorkspaceRoot[]        // { id, path, label }
 ├─ addRoot(path) / removeRoot(id) / reorderRoots
 └─ activeRootId                    // 决定新终端/新文件的落点
        ↓
FileExplorer 渲染多根(每个根一个可折叠子树,VS Code 风格)
```

- 持久化:复用现有 `spaces` 模块的序列化机制(src/modules/spaces/lib/serialize.ts + store.ts,已支持 per-space 配置持久化),在 space 配置中扩展 `roots: string[]`,沿用 `useSpacePersistence` 的读写管线,不新引入存储方案。
- 根集合变更时,`useFileTree`(explorer/lib/useFileTree.ts)按根分别维护 `TreeState`,节点 key 用根 id 前缀隔离。
- 新文件/新建终端落点:取 `activeRootId` 对应的根。

### 2.2 盘符导航(Windows,对应 R2)

- **Rust 新增命令** `fs_list_drives`(src-tauri/src/modules/fs/tree.rs):
  - Windows:枚举 `A:`~`Z:` 中存在的盘符(`GetLogicalDrives`),返回 `["C:", "D:", ...]`;
  - Unix/macOS:返回 `["/"]`(单根,保持现有行为)。
- **前端**:文件树根之上增加"盘符条"(仅 Windows 且 roots 为空/或始终显示在根集合之上),点击盘符 → 展开该盘根目录。
- **路径归一**:`parseOsc7`/`dirname`/`parentOf` 对 `C:`/`C:/` 形态补充分支处理(TERAX.md 已规定 canonical path 为 forward-slash,`C:/` 的 dirname 应为 `C:` 并在 Rust 侧 `resolve_path` 正确处理 `C:` → `C:/`)。
- 同时给文件树补"上级目录"面包屑/按钮(现有 `parentOf` 只到无 `/` 为止,断链点就是盘符)。

### 2.3 终端面板布局重构(对应 R8,用户决策 5)

**目标布局**(用户原话:终端出现在中间文件阅览器的右侧、水平放置若干个终端,不抢占顶部 tab 空间):

```
┌───────────────┬──────────────────────────┐
│ 侧边栏 │ 主区域(文件类 tab)   │ 终端面板(右侧,可折叠/可调宽)│
│(explorer)│ TabBar+EditorStack    │ 终端 tab 条(横向,可多个)    │
│           │ preview/markdown     │ TerminalStack(分栏能力保留)│
└───────────────┴──────────────────────────┘
```

- **tab 体系拆分**:`useTabs` 中的文件类 tab(`editor`/`preview`/`markdown`)留在主区域;`terminal` 类 tab 移入独立的**终端面板**集合(新 `useTerminalPanel` 或复用 `TerminalStack` 数据源改造);
- **布局**:`react-resizable-panels` 水平分割 主区域 | 终端面板(默认右侧,可拖拽调宽、可一键折叠);
- **面板内**:终端 tab 条横向排列在面板顶部(小尺寸标签),复用现有 xterm 挂载/分栏能力,保持 PTY 后台常驻;
- **迁移兼容**:spaces 持久化的 tab 序列化、关闭守卫、快捷键(tab.new 等)需按新模型适配;终端面板开关作为新快捷键/命令。

### 2.3b 一键唤醒终端(对应 R3)

- 文件/文件夹上下文菜单新增 **"在此路径打开终端"**:
  - 文件夹 → cwd = 该文件夹;文件 → cwd = 其父目录(TERAX.md 注释明确:编辑器打开新终端不应劫持用户工作目录,但**用户显式操作**时以目标路径为准,不违反原设计意图);
  - 落地到右侧终端面板:调用面板新建终端逻辑,`cwd` = 目标路径;
- 双击/单击行为保持现状(单击展开/选中,双击打开文件);终端唤醒走右键菜单。

### 2.4 中英文切换(对应 R4,从零搭建)

- **轻量自建 i18n**(不引第三方,契合项目"超轻量"质量线,~几 KB):
  - `src/lib/i18n/`:`zh.ts` / `en.ts` 字典、`I18nProvider`(React context)、`useT()` hook、`t(key, params)` 函数;
  - 语言偏好持久化到现有 `preferences` store(src/modules/settings/store.ts 新增 `locale` 字段,沿用 `KEY_*` 模式)。
- **覆盖范围(分两批)**:
  - 第一批(核心):侧边栏(explorer 视图标题、右键菜单、新建文件/文件夹/重命名/删除)、状态栏、设置窗口全部 tab、新建终端菜单、命令面板标题、通用按钮(确认/取消/保存/覆盖);
  - 第二批(扩展):编辑器面板(查找/替换/行号定位)、对话框(关闭确认、打开大文件确认)、explorer 搜索占位符。
- 文案集中在字典文件,组件内改用 `useT()`;不翻译终端内 shell 输出与文件名。
- 设置窗口新增"语言/Language"下拉。

| 模块 | 前端 | Rust | 连带清理 |

3. **保留项建议**:`secrets.rs`(keyring,成本极低,留作以后接本地模型可用)、`lsp/`、`preview/`、`markdown/`、`theme/`、`spaces/`(多根持久化依赖它)、`settings/`(语言切换入口依赖它)、`shortcuts/`、`command-palette/`(改名/保留,可用作中英切换入口)。
4. **需要你拍板的两个点**:
   - CLI 侧车(terax-cli,src-tauri/crates/terax-cli + externalBin)是否保留?它依赖 control-protocol crate。若不用外部 CLI 控制,可连同 `createUpdaterArtifacts` 一起裁,减小打包面;保守方案是保留不动。
   - `ai/` 全部裁还是留"本地模型"口子?若你后续仍想用本地 Ollama/LM Studio,建议保留 `net.rs` 的 `lm_ping` 与 secrets,只裁 cloud provider 前端。

## 四、风险与注意事项

0. **终端面板重构优先**:R8 是结构性改动,影响 tab 体系/布局/快捷键/spaces 序列化。先行完成,后续裁剪与 i18n 都在新布局上叠加,避免返工。
1. **AiComposerProvider 移除时机**:TERAX.md 明确警告该 Provider 必须无条件挂载(条件挂载会 remount 整树重启 PTY)。裁剪阶段直接整体移除,无此问题;但**在裁剪完成前不要**做任何条件化改动。
2. **explorer 与 git 装饰耦合**:`useGitStatus`/`gitStatusUtils` 深嵌 FileExplorer 行渲染,裁 git 时必须同步清掉,否则 tsc 报错或运行时空指针。
3. **Rust 命令裁剪顺序**:lib.rs 的 `removeUnusedCommands: true` 已开,前端不再 invoke 的 git/agent/control 命令可安全移除,但需先确认**没有其他调用方**(用 `rg` 全仓搜 `invoke("git_` / `invoke("agent_` 等)。
4. **crates/terax-control-protocol 与 CLI**:若保留 CLI 侧车,control-protocol crate 与 `control.rs` 需至少保留编译面(可从 lib.rs 摘掉命令但保留 crate);若裁 CLI,externalBin 与 build:cli 脚本要一起处理,tauri.conf.json 的 `externalBin` 项删掉。
5. **多根与 WSL**:现状 workspace 支持 WSL 环境;多根初期仅支持 Local(Windows 盘符 + Unix 路径),WSL 根后续再扩,避免范围膨胀。
6. **i18n 工作量大头在文案迁移**:71k 行前端代码,建议第一批只覆盖"用户高频可见"文案(见 §2.4),不追求 100% 覆盖,避免改动面失控。
7. **测试同步**:删除模块时对应 `*.test.ts` 必须同步删/改,否则 `pnpm test` 红。
8. **非 git 仓库**:当前目录无 `.git`。执行前建议 `git init` + 首次提交作为回滚基线(强烈建议,不改代码前先做)。

## 六、决策结果(已确认,2025-08 反馈)

5. **终端唤醒交互**:✅ 右键菜单;**布局**:终端从顶部 tab 剥离,独立右侧面板,可水平放置多个终端(R8)。
6. **git init 建基线**:✅ 需要,执行前先建。
